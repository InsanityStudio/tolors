# TOLORS Quoter
This website quotes [TOLORS](https://scratch.mit.edu/discuss/post/9319489/) - short for The Official List of Rejected Suggestions - a list of suggestions which have been officially rejected by the Scratch Team. This means threads that have been rejected are not allowed and will be closed unless they provide a solution to the problem which caused the suggestion to be rejected.

If you want to have a thread with a rejected suggestion closed, you should reply to the thread with a quote from TOLORS. The problem is this quote can be annoying to find, copy, paste and format.

This project solves that problem. Search for keyword/s or a TOLORS number and click a result that matches to copy it to your clipboard.

https://insanitystudio.github.io/tolors/

## Context

I originally created Pasteify in January 2023 as a project for auto-copy and pasting various responses such as duplicate posts and posting in the wrong forum, and it featured a basic TOLORS quoter. That project was discontinued in February 2023 due to projects of that type being seen as spammy and unconstructive on the forums, which I agreed with.

I spun the TOLORS quoter part off into The Ultimate TOLORS Quoter in May 2023 with a much better system where the numbers, titles and even text of the topic could be searched then copied. However, the project was somewhat annoying for me due to controversies surrounding suggestions getting removed, name changes and eventually the topic changing owners. When that happened, I immediately discontinued my project. The new owner could change the syntax to break my code.

## This project

This is my latest iteration. It uses a website format which is much easier as it simply involves typing your query or TOLORS number and clicking the entry you want to copy to instantly copy it to your clipboard, then going to the thread and pasting.

It is entirely vibe coded. It still follows the philosophy I made TUTQ with - making foruming more efficient by taking the boring parts out of the equation, yet not making it unconstructive. Vibe coding only takes off the burden for me to manually maintain the code, while giving the user the exact same process of searching for the rejected suggestion they want and copying and pasting it.

Updates to TOLORS are simply a matter of going to [the source text](https://scratch.mit.edu/discuss/post/9319489/source), clicking Ctrl+S and uploading the scratch.mit.edu.txt file to this repo. The website does the rest.
